# 架构说明

## 分层

```text
gt_automation/ui       桌面界面、主题、交互状态
gt_automation/app      应用入口
gt_automation/session  HAR 导入、拆分配置校验、迁移和持久化
gt_automation/process  子进程启动与实时输出
gt_automation/logging  应用与任务日志
daily_welfare_claim    每日福利领域逻辑与 CLI
siyi_star_auto         四艺星盘领域逻辑与 CLI
```

## 数据流

```text
HAR
  ↓ session_store.extract_gt_session
account.json + task/
  ├─ UI 读取账号和各任务能力
  ├─ daily_welfare_claim.py --data-dir .
  └─ siyi_star_auto.py --data-dir .
```

界面不会把 HAR 传给任务进程。任务进程只接收 `--data-dir` 路径。

运行时使用三个配置文件：

```text
account.json                 共享账号信息
task/daily_welfare.json      每日福利登录快照、初始化帧、最近奖励
task/siyi_star.json          四艺星盘登录快照、初始化帧、活动状态
zhaoxian.json                招贤活动、请求 payload 和执行结果
qiluo_jingyi.json            绮罗锦衣直购配置与奖励结果
```

导入星盘 HAR 时只更新 `task/siyi_star.json`；导入招贤 HAR 时只更新
`zhaoxian.json`，不会覆盖每日福利任务。
导入绮罗锦衣 HAR 时只更新 `qiluo_jingyi.json`。
界面通过任务文件是否存在显示“已导入每日福利”“已导入四艺星盘”。

## 数据边界

- `account.json` 与 `task/` 保存在解压目录；
- 缺少对应任务文件时，界面禁用该任务；
- 配置文件包含敏感登录凭证，权限固定为 `0600`；
- 每次运行日志写入解压目录下的 `logs/`；
- 本机界面设置写入 `runtime/settings.json`；
- HAR 建议统一放在 `data/har/`。

## 扩展方式

新增任务时应在领域脚本中提供稳定 CLI，然后由 UI 的进程运行层组合参数。
UI 不直接导入任务执行函数，避免网络与业务逻辑阻塞 Tk 主线程。
